# Pixel Run & Leap 設計規格

日期：2026-09-10
狀態：已實作完成（最後更新：2026-09-10，對應 commit `75f65e8`）

> 本文件初版為實作前設計，實作過程中發生的差異已在各章節以「實作備註」補記，
> 完整功能演進見 [實作歷程](#實作歷程) 與 [變更記錄](../../../CHANGELOG.md)。

## 目標

建立一個僅供私人本機使用的 HTML5 2D 網頁遊戲，參考 `ffx0s/mario-html5` 的遊戲內容與素材，名稱與外層介面改為 `Pixel Run & Leap`。

第一版目標是接近參考專案的完整單人關卡流程，而非只有畫面展示。

## 已確認限制

- 技術：Phaser 3 + JavaScript。
- 建置：Vite 8（`chunkSizeWarningLimit: 1300` 容納 Phaser 約 1.2MB 單一 chunk）。
- 測試：Vitest 5（純邏輯單元測試）+ Playwright（Chromium 瀏覽器測試，單 worker）。
- 品質：Prettier + ESLint + `.editorconfig`，`npm run check` 一次執行格式、Lint、單元測試與建置。
- 平台：桌面與手機瀏覽器。
- 使用範圍：私人本機使用。
- 素材：使用參考專案的圖片、地圖、音樂與音效。
- 品牌：使用 `Pixel Run & Leap` 名稱，不保留參考專案的網站品牌。
- 本階段：只完成設計分析，不開始遊戲實作。

## 技術方向

Phaser 3 負責 2D 遊戲執行環境，包括畫面、Sprite、動畫、碰撞、攝影機、地圖、音效與場景。JavaScript 負責遊戲規則與物件行為，降低初期設定與 AI coding 迭代成本。

原生 Canvas 與 React + Phaser 外殼不列為第一版方案：前者需要自行實作較多遊戲基礎能力，後者會為目前的單一遊戲增加不必要的整合複雜度。

## 場景架構

```text
BootScene
  初始化 Phaser 設定

PreloadScene
  載入圖片、Sprite、地圖、音樂與音效

TitleScene
  Pixel Run & Leap 標題畫面
  開始遊戲與音效開關

GameScene
  玩家、敵人、磚塊、金幣、道具與終點
  地圖捲動、碰撞與 HUD

GameOverScene
  生命歸零、重新開始

LevelCompleteScene
  顯示分數、通關結果與下一步操作
```

實作備註：實際僅有 `PreloadScene`、`TitleScene`、`GameScene` 三個場景（`src/main.js`）。
`BootScene` 併入 `PreloadScene`；Game Over 與通關未獨立成場景，
改在 `GameScene` 內以結果文字顯示，`R` 重來、`T` 返回標題。管道傳送、水管目的地、
互動磚塊（`callback: breakable`）解析自 Tiled `modifiers` 層。

預計將程式碼依功能拆分為 `scenes/`、`entities/`、`systems/` 與 `assets/`，避免所有邏輯集中在單一場景。

## 遊戲功能

- 左右移動與跳躍。
- 踩踏敵人（Goomba、烏龜；踩踏後顯示壓扁/縮殼外觀再移除）。
- 撞擊互動磚塊（`breakable` 回呼，磚塊移除並播放音效）。
- 頂問號磚（`questionMark`，gid41）：每顆只觸發一次，觸發後換成用過素色磚（gid40），
  再頂只有 `smb_bump` 音效。生成內容由 Tiled `modifiers` 層標記決定，
  無標記的問號磚出金幣；19 顆問號磚中有 6 顆有標記。
- 頂出的金幣直接上冒加分；蘑菇/1UP 從磚頂升起後水平滑行（遠離玩家方向，撞牆反彈）；
  花升起後靜止待吃；星星滑行加落地彈跳。滑行道具掉出地圖自動移除。
  無相鄰問號磚的標記（如懸空 1UP）維持靜態擺放。
- 水管傳送（下方向鍵 + 管道 `direction: down` 屬性 + `dest` 目的地）。
- 收集金幣（每枚 +100 分）。
- 蘑菇（超級）、火焰花（火焰能力 + `Z` 發射火球）、星星（8 秒無敵）、1UP（+1 生命）。
- 火球擊敗敵人（+100 分）。
- 玩家受傷、死亡與生命數（掉出地圖、被敵人撞到、倒數歸零皆扣生命；歸零進 Game Over）。
- 分數、倒數時間與通關時間獎勵（剩餘時間 × 10）。
- 旗幟終點判定：觸發區覆蓋整根旗杆（杆頂 16×16 小旗僅裝飾），碰到杆身任一高度即過關。
- 關卡完成與重新開始（`R`）、返回標題（`T`）。
- 背景音樂、事件音效與標題畫面音樂/音效開關（狀態於場景間共用）。
- 玩家、Goomba、金幣、星星、烏龜像素動畫；死亡動畫（`mario/dead`）。
- `?debug=1` 顯示碰撞框、FPS、座標與狀態；`?test=1` 固定初始狀態與
  `window.__pixelRunLeap` 測試查詢介面（含傳送、狀態讀取）。

### 桌面操作

```text
左方向鍵 / A：向左
右方向鍵 / D：向右
下方向鍵：進入水管
Space：跳躍
Z：發射火球（火焰能力時）
P：暫停/繼續
R：重新開始（非進行中時）
T：返回標題（非進行中時）
```

實作備註：設計稿的 `M` 音效開關未實作，改為標題畫面的音樂/音效開關按鈕。

### 手機操作

畫面底部提供固定觸控按鈕：

```text
[ 左 ] [ 右 ]              [ 火 ] [ 跳躍 ]
```

觸控按鈕與鍵盤共用同一套輸入狀態，遊戲規則只維護一份。

實作備註：較設計稿多一顆「火」按鈕，對應火焰能力的觸控火球輸入。

## 視覺與介面

保留參考素材的像素風格，外層介面改為 `Pixel Run & Leap`：

- 自有遊戲標題與開始畫面（含 HTML 開始按鈕）。
- 像素風邊框與深色藍色背景；啟用 Phaser 像素渲染（`pixelArt`、`roundPixels`、關閉抗鋸齒）。
- HUD 顯示分數、金幣、生命、能力（小型/超級/火焰/無敵）與時間，文字換行避免與觸控按鈕重疊。
- 暫停提示與通關/Game Over 結果文字。
- 桌面版隱藏觸控按鈕，手機版顯示觸控按鈕（加大尺寸與按壓回饋）。
- 遊戲區維持固定比例，使用縮放與置中避免變形。
- 遊戲 Canvas 與 HTML/CSS 外層 UI 分離。

## 狀態管理

集中管理以下遊戲狀態（`src/game/gameState.js` 不可變模組，`src/main.js` 場景只負責呈現與碰撞）：

- 玩家生命（初始 3）。
- 分數。
- 金幣數。
- 剩餘時間（初始 300 秒，每秒遞減，歸零進 Game Over）。
- 能力（`small` / `super` / `fire`）與無敵旗標。
- 暫停旗標。
- 流程狀態（`playing` / `complete` / `game-over`）。
- 當前關卡（單一參考關卡 `super-mario.json`，237×15 格）。
- 音效與音樂開關（`window.__pixelRunLeapAudio`，於場景間共用）。

場景之間只傳遞必要資料，避免不同物件各自維護分數或生命。

## 錯誤處理

- 素材載入失敗時顯示明確錯誤訊息。
- 地圖資料格式錯誤時阻止進入遊戲並顯示診斷資訊。
- WebGL 不可用時嘗試退回 Canvas。
- 音樂被瀏覽器阻擋時等待使用者互動後播放。
- 視窗尺寸變更時重新計算遊戲區與觸控按鈕位置。

- 桌面瀏覽器可使用鍵盤完成關卡流程。

- 玩家死亡、重新開始、通關與返回標題流程正常。

## 已知限制與後續工作

- `src/main.js` 約 1100 行，三場景與所有系統集中單檔，違反「依功能拆分」規範，
  後續應拆為 `scenes/`、`entities/`、`systems/`。
- 旗杆過關、問號磚頂出僅以臨時 Playwright 測試驗證，未留存常駐迴歸測試。
- 花朵在地圖無標記，僅能透過無標記時的固定 fallback 取得。
- 瀏覽器測試僅 Chromium，未覆蓋 Firefox/WebKit 與真實行動裝置。
- 單元測試僅覆蓋 `gameState`，`togglePause` 與輸入轉換、碰撞計算、關卡解析尚無覆蓋。
- `?test=1` 測試介面（含傳送作弊）在正式建置未剝離，應以 `import.meta.env.DEV` 包裹。
